# BYU-Idaho Brand Style Guide audit

Date: October 19, 2026
Plugin version: 0.1.11
Repository revision: fd7d0351a3bfbd7507f14f945f33cbf9ef59b348

## Assessment

The plugin is a useful brand reference, but it is not yet a complete production workflow for all requested formats. The core palette, official logo size and clear space, photography permissions, basic voice, and most campus advertising limits agree with the public site. Several instructions and references are stale or incomplete, the asset set has compatibility and campaign limitations, and export/accessibility checks are missing.

| Criterion | Result |
|---|---|
| Correctness | Mostly aligned with current public guidance; society routing, source drift, font transition, and campaign-mark handling need attention. |
| Asset presence and usability | All 9 bundled assets are present and decode/open. All 3 Markdown download links resolve. WebP logos fail the DOCX insertion check. Both PPT templates carry anniversary branding. |
| Adaptability | Presentation templates and image prompts are supported at a basic level; DOCX/PDF/infographic production and accessibility checks are not explicitly routed. |
| Speed | Reasonably small package, but instructions repeat policy and can prompt unnecessary network reads. No live model latency benchmark was performed. |

## Scope and method

Checked the public branding hub and linked guidelines, 36 distinct public HTML pages including the linked society policy and accessibility guidance, plus relevant sections of the linked 76-page Written Style Guide. This included terminology, institutional naming, time formatting, accessibility, and digital communication; the proper-name directory was not exhaustively validated. The saved public crawl covers 35 canonical URLs; the additional academic society policy was inspected separately.

Compared the repository's five plugin text/configuration files with the published plugin: all matched semantically. Inspected every bundled asset; checked Office ZIP integrity and internal relationship targets; decoded each logo; tested DOCX logo insertion; imported both POTX files into the available presentation library; rendered both decks as contact sheets and sampled full-size slides; rendered the email signature; rebuilt and inspected the distributable ZIP.

This does not establish that every BYU-Idaho webpage or restricted internal policy has been examined. Linked SharePoint office/PPT/signature resources returned HTTP 401 without authentication. The connected SharePoint tool resolved the Identity site but could not read the Site Pages content or resolve the custom template-library folder. The bundled files could therefore not be certified as the latest SharePoint revisions. PowerPoint and Outlook desktop applications were not used for testing.

## Findings by priority

### 1. High: The PowerPoint templates contain a limited-use anniversary mark

Both `assets/templates/powerpoint/BYUI_Blue_Template.potx` and `BYUI_White_Template.potx` include an EMF footer with the university mark and “25 YEARS.” It appears in the imported presentation render, including slide 16. The skill's PowerPoint instruction recommends both files for general presentations and says to retain their logo treatment, while its anniversary check is applied specifically to LinkedIn banners.

The official [Other Logos page](https://www.byui.edu/branding/logos/other) limits anniversary marks to approved promotional materials/merchandise during the anniversary period. The page does not give a precise end date, so this audit does not label the mark expired. The plugin should classify these templates as anniversary-branded and check current authorization before recommending them as general templates. Obtain a current approved generic template when needed; do not edit or crop the anniversary artwork to manufacture a new mark.

The footer was also absent from a LibreOffice PDF rendering of sampled source slide 16, although it was visible in the presentation library's render. This is a renderer-dependent portability issue requiring visual comparison.

### 2. High: The root manifest violates its own declared schema

`plugin.json` contains six top-level properties not allowed by the declared [Agent Plugins schema](https://agent-plugins.org/schemas/1.0.0/plugin.schema.json): `logo`, `logoDark`, `composerIcon`, `composerIconDark`, `brandColor`, and `brandColorDark`. That schema sets `additionalProperties` to false.

The current host has accepted this package, but strict portable validation rejects those fields. Put host-specific metadata in supported extension fields and validate the effective manifests. Preserve the existing package name, plugin identity, display name, prompts, and audience.

### 3. High: Bundled logos are incompatible with the DOCX library

All four standalone logo tiles are RGB WebP files, 800 × 800 with solid backgrounds. All four decode correctly, but `python-docx` rejects every one with `UnrecognizedImageError`. They are usable for web/image workflows, not directly through that DOCX insertion path.

Add approved PNG/JPEG versions for Office workflows and obtain approved vector/transparent variants where needed. A lossless format conversion can preserve decoded pixels, but it does not create a vector master, improve resolution, or undo the original lossy compression. Do not redraw, recolor, or remove the supplied backgrounds to create missing variants. The [Official Logo page](https://www.byui.edu/branding/logos/official) links an approved package with PNG, JPEG, and vector formats.

The visible mark occupies roughly 442 × 256 pixels inside each tile. Its 256-pixel visible height corresponds to about 0.85 inches at 300 pixels/inch; enlarging beyond that reduces effective print resolution. The blue WebP tiles have a dominant color of RGB 0,109,182, one green-channel level below the official 0,110,182, consistent with image compression. Prefer approved original production files for exact color work.

### 4. High: The available presentation round trip loses native charts

Each original POTX contains 32 slides, 27 layouts, one master, and seven native chart parts. Both import successfully. A direct import/export through the available `@oai/artifact-tool` preserved 32 slides, 27 layouts, and one master but produced zero native chart parts. The original templates are structurally valid; this is a limitation of the tested conversion path.

Instructions should require preserving or rebuilding charts as native editable charts when editability is requested, with a saved-output check. A good-looking preview alone is insufficient proof. Do not promise that using the template automatically preserves editable chart data.

### 5. Medium: Society guidance uses an old platform and no longer reaches its cited rules

`SKILL.md` says societies should use I-Belong. `references/institutional-brand-architecture.md` repeats that platform, a sponsor-logo requirement, and specific custom-logo exception categories as claims of the Campus Logo Guidelines.

The cited `/branding/logo-guidelines` now redirects to the general Logos page, which does not establish those detailed claims. The current [Student Groups & Societies page](https://www.byui.edu/branding/student-groups-and-societies) and [society policy](https://www.byui.edu/academic-societies/society-leadership/policies#society-marketing-and-branding) direct societies to myBYUI Groups. Public marketing is for society awareness/recruitment; society activities, speakers, and event announcements belong in member communications. Temporary artwork can be used up to one year, with no permanent society logo. The [Department Logos page](https://www.byui.edu/branding/logos/department) addresses campaign marks and requires contacting University Communications.

Replace the old platform name and route society requests through these current sources. Revalidate individual historical requirements rather than presenting them as newly verified rules.

### 6. Medium: Output requests can receive a prompt instead of a deliverable

The skill's Answer format says that new assets normally receive a creative direction or production prompt. It does not explicitly route a user asking for a file to the available authoring tools, nor distinguish a requested editable source from a final export. DOCX, PDF, and infographics are not covered as production workflows.

Add concise output routing with an explicit fallback when the host lacks the necessary tool:

| Output | Required production guidance |
|---|---|
| DOCX | Use an applicable approved office template; retain semantic headings/lists and table headers; embed supported logo images; add alt text; render and inspect. An email-signature DOCX is not a general university document template. |
| PPTX | Inspect and reuse the approved template's layouts; apply campaign and font checks; remove instruction/sample slides; preserve requested slide count and native charts/tables; export PPTX and inspect rendered output. |
| PDF | Export from the validated editable source; check selectable text, page fit, fonts, reading order, tags/bookmarks where supported; disclose any missing accessibility feature. |
| Images | Choose channel dimensions and file type; render exact text and place approved logo assets separately from generated artwork; inspect visible logo size, contrast, cropping, and resolution. |
| Infographics | Verify data and sources; use appropriate native charts where feasible; do not rely on color alone; provide accessible text/alt descriptions and the requested editable or raster output. |

These are workflow recommendations, not invented university rules or requirements for unavailable host tools.

### 7. Medium: Accessibility is mentioned but not operationalized

The plugin lacks explicit checks for semantic headings, image alt text, document/slide reading order, table headers, meaningful links, contrast, and accessible PDF export. The university's [Accessibility Guidelines](https://www.byui.edu/accessibility-services/web-accessibility-guidelines) covers Word, PowerPoint, online content, and PDF production. Its old application-specific menu instructions need adaptation to the current tool; preserve the principles rather than copying obsolete UI steps.

Approved palette colors are not automatically accessible in every text/background combination. Accessibility checks should be part of output validation, especially for charts and infographics.

### 8. Medium: Several current channels and font details are omitted

The source inventory lacks direct entries for departmental logos, society guidance, merchandise, IBC, external organizations, campus email, myBYUI, paid digital advertising, text messaging, and accessibility. The reference mentions social-media review but the main skill omits the required full-time manager review and annual training requirements.

The [Digital Display Guidelines](https://www.byui.edu/branding/digital-displays) also specifies JPEG for static DSN graphics and explicitly says a logo is optional; the current main skill gives the dimensions but omits those useful output details.

Keep these as short, task-specific references. For example, the [Video guidelines](https://www.byui.edu/branding/video) distinguishes department social video from other official video, and [Text Message Guidelines](https://www.byui.edu/branding/text-messages) disallows general promotional event/workshop texts. These distinctions matter when adapting one message to multiple channels.

The [Fonts & Typefaces page](https://www.byui.edu/branding/fonts-typefaces) explains the News Gothic-to-Acumin transition, licensing/access through Adobe Fonts, and availability through IT or qualifying student access. The plugin does not check font availability. Both POTX files contain Arial master text, Calibri theme declarations, and a legacy NewsGoth chart-font declaration; fonts are not embedded. A public-facing output needs a font preflight rather than silent substitution.

### 9. Low: Asset path and internal naming need cleanup

The opening of `references/official-guidance.md` says logos are at `../assets/` relative to the skill folder. That path does not exist. From `skills/byui-brand-guide/`, the plugin assets are `../../assets/`. The three actual Markdown template links do resolve correctly. Plain `assets/...` references should explicitly say they are relative to the plugin root.

The internal skill heading still reads “BYU–Idaho Brand Guide,” despite the display title being “BYU-Idaho Brand Style Guide.” The package slug can remain unchanged.

The dark plugin icon uses `#14243A`, which is not in the published core/accent palette. Treat it as a UI-specific design decision rather than an official dark-mode brand color, or use an approved dark color. No official dark-mode palette was found in the checked public branding pages.

## Speed assessment

The main skill has 2,265 words / 16,523 bytes; supporting Markdown references add 17,383 bytes. It is not excessively large, but is not organized for minimal task-specific reading. Much of the reference material repeats policy and the history of previous conflicting claims. The archive is about 6 MB; PowerPoint templates account for almost all binary storage. Reducing binary asset size is unlikely to be the most useful first optimization because those bytes do not need to become prompt text.

Recommended improvements:

1. Keep a short core skill with shared brand constants and a task/output routing table.
2. Load only relevant source notes, channel constraints, and output recipes; keep historical reconciliation notes out of routine production.
3. Add a compact asset manifest with exact plugin-relative paths, formats, dimensions, fonts, source URLs, campaign status, and hashes.
4. Batch necessary live checks and reuse already fetched evidence within a task. Check task-relevant live requirements, not the entire site for every output.
5. Reuse selected template layouts and inspect changed output instead of processing all 32 source slides unnecessarily on every request.
6. Share the same validated content and brand settings across multiple exports.

The local template import checks took about 0.2–0.8 seconds per file in the tested process. These are observations of one local importer, not a benchmark of model response time, end-to-end export, or other hosts. No percentage speedup is claimed.

## Conflicts within the official sources

The website itself contains errors or competing instructions that the plugin should record rather than silently resolve into invented policy:

- The Color Guide labels white `#FFFFFF` but lists RGB 0,0,0 in that row. It also gives gray `#949598` but RGB 148,148,148; the hex decodes to 148,149,152. Preserve correctly identified color values, flag disputed production conversions, and seek clarification when exact print specifications matter.
- Fonts & Typefaces displays “Ariel” in one heading but explicitly says Arial in its usage/FAQ text. Arial is the supported reading.
- The Written Style Guide section 2.5.5 describes a CES-level en-dash exception; its terminology entry later says never to use an en or em dash. The general public quick reference uses the hyphen. Use the public hyphen form for ordinary communications; confirm CES-specific requirements with University Communications.
- Time-format discussion in the PDF contains inconsistent wording, while the public quick reference clearly prefers a.m./p.m. in running text. The PDF also permits AM/PM on posters/programs. Avoid converting the running-text default into a blanket ban across every medium.

## Recommended implementation order

1. Correct portable manifest metadata and supply Office-compatible approved logo files.
2. Qualify anniversary PowerPoint assets and update society/source routing.
3. Add output routing, accessibility/format checks, font checks, and native chart preservation tests.
4. Split and index supporting references for faster task-specific reading.
5. Validate representative DOCX, PPTX, image/infographic, and PDF outputs before publishing an updated release.
